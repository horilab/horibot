- Agent 도구: `model: fable`, `effort: high`, 새 에이전트. 프롬프트는 아래 "맡기는 일"부터 끝까지를 그대로 준다.
- 생각 깊이를 high로 고른 까닭: 부품 하나의 자리라 링크 묶음(xhigh)보다 작다. 다만 파이 높이, 선 길이, UR3e와 같은 자세 시험, 책상에 무는 판의 크기가 얽혀 있어 medium으로는 모자란다.
- 네 단계로 한다 (CLAUDE.md): Fable은 먼저 읽고 묻기만 한다 → Opus가 답을 정해 같은 에이전트에 SendMessage로 보낸다 (계산으로 답이 나오는 기술 갈림길은 Opus가 고른다) → Fable이 설계하고, 취향이나 정한 조건을 바꿔야 하는 갈림길에서는 멈추고 돌아온다 → Opus가 검사를 다시 돌리고 3D 페이지로 보인다.

## 맡기는 일

호리봇 베이스에서 서보 어댑터(Waveshare Bus Servo Adapter (A))를 둘 자리와 다는 방법을 다시 정하고 그린다. 지금 자리(컨트롤러 파이 밑, `parts/pi_mount.py`의 `adapter_parts`, `parts/base.py`의 `ADAPTER_*`, `ADAPTER_TALL`, `TRAY_UNDER`)에는 위에서 꽂는 서보 플러그와 선이 들어가지 않는다. 첫 답에서는 설계하지 말고, 아래를 읽은 뒤 묻기만 한다: 문제를 잘못 잡은 곳, 빠진 조건, 사용자가 정할 갈림길. 물을 것이 없으면 그렇다고 하고, 고를 안을 한두 줄로 적는다. 답을 받은 뒤에 설계한다.

### 할 일

1. 어댑터 자리와 다는 방법을 정하고 그린다 (책상에 무는 판, 파이 판, 필요하면 작은 받침 부품). 견준 안과 고른 까닭을 남긴다.
2. 어댑터에서 나가는 선(서보 선 둘, 서보 전원선, 파이와 잇는 USB 선 UM2)의 자리와 길을 다시 본다. 서보 선 두 줄은 `studies/wiring.py`의 길이도 고친다.
3. `pi_mount.adapter_parts`를 실제 모양(위로 꽂은 플러그와 선 포함)으로 고친다.
4. 검사를 돌린다: `uv run python -m horilab_design.parts.pi_mount`, `... parts.base`, `... placement`(겹침과 틈), `... studies.ur_arm compare`(UR3e와 같은 자세 시험, 지금 73.5%), `... studies.wiring`, `... studies.rest_pose`, `uv run pytest`. 책상에 무는 판은 `... slicing plan --name adapter-check base.base_plate pi_mount`로 출력 판에 들어가고 검사를 통과하는지 본다 (낸 파일은 Opus가 정리한다).
