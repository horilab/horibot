# 0042. 떨림과 처짐: 서보 게인과 처짐 보정을 다 만든 팔에서 재서 고른다

- 상태: 채택 (재는 순서, 통과 기준, 만든 것. 고른 값은 재서 더한다)
- 날짜: 2026-11-28

## 배경

- 처음 전원(2026-11-28, [0034](0034-first-power-tools.md)의 처음 전원 결과)에서 팔이 천천히 움직일 때 떨렸다 (사용자가 봤다). 버틸 때는 목표보다 처진 채 선다: 어깨 버티기 30 cm 자세에서 도구 끝이 높이로 8.4 mm 처졌다 ([0028](0028-ur-style-joints.md)의 결과).
- 서보 게인(P 32, D 32, I 0은 첫 덤프 값 그대로), 실행 루프의 처짐 보정(있지만 꺼 둠), 따라가기 오차 기준(시험값 10°)은 "다 만든 팔에서 재서 고른다"로 남겨 두었다 (`data/robot.toml`, [0012](0012-precision-metrics.md), [0032](0032-run-loop.md)). 상대 정확도 목표(100 mm에 1 mm)는 처짐을 보정해야 된다 (0012).
- 그래서 처음 전원 기록으로 떨림이 어디서 오는지 가르고, 고를 대안, 재는 순서, 통과 기준을 재기 전에 정한다.

### 기록으로 본 것

기록은 `records/run/2026-11-28_035312_run-hori1`(어깨 버티기), `records/run/2026-11-28_040105_run-hori1`(관절 하나씩 끝까지), 손목 시험대의 J5 기록(`records/run/2026-11-18_000714_run-crazyhappy`, `2026-11-19_062829`, `2026-11-19_064044`)이다. 지표는 셋이다:

- 떨림: 관절 하나만 움직이는 동안 1초마다 (읽은 위치 - 서보에 쓴 목표)에서 0.2초 이동 평균을 뺀 값의 폭(가장 큰 값 - 가장 작은 값).
- 뒤처짐: 움직이는 동안 |읽은 위치 - 목표|.
- 처짐: 버티는 동안 읽은 위치 - 목표.

숫자는 `uv run tools/run_metrics.py <기록 폴더> ...`가 낸다 (아래 만든 것의 3).

본 것:

- 떨림은 움직일 때만, 모든 관절에서 난다. 1초 폭의 가운데 값이 0.18 ~ 0.25°(2 ~ 3칸, 한 칸 0.088°)이고, 가장 큰 것은 J3 0.67°(-135° → 160°를 7.5°/s로), J5 0.45°, J4 0.40°, J1 0.37°다. 1초에 3 ~ 6번 떤다. 버티는 동안 위치는 1칸 안에서만 오갔다 (어깨 버티기에서 J2가 4초에 한 박자 한 칸 더 읽힌 것 말고).
- 꼴은 스틱슬립(서 있다가 미끄러지기를 되풀이)이다. J3가 길게 돌 때 목표는 고르게 가는데 위치는 섰다 뛰었다 한다. 서 있는 동안 목표와의 차이가 벌어지며 서보 출력(부하)이 차이에 비례해 커지고(-17.6 → -25.6%), 정지 마찰을 넘으면 미끄러져 따라잡은 뒤 출력이 내려가 다시 선다. 서보가 읽은 속도가 0과 200 step/s 사이를 오간다. 중력이 걸리지 않는 J1도 같은 꼴이다 (출력 -7.2 ~ +2.4%: 움직이기 시작하는 데 7%쯤 들고, 움직이는 동안은 0 ~ 2%다).
- 서보는 목표와의 차이에 비례해 출력을 낸다 (부하가 차이와 같은 꼴로 움직인다). 그래서 버틸 때는 버티는 토크만큼 처진 채 선다 (어깨 버티기에서 J2 0.4 ~ 1.5°, J3 1.4 ~ 1.9°, J4 1.0 ~ 1.2°). 움직일 때는 마찰과 중력만큼 뒤처진다 (가장 많이 J2 3.34°, J3 2.81°).
- 손목 시험대의 J5(짐이 가볍다)도 같은 지표로 가운데 0.18°, 가장 큰 것 0.29 ~ 0.75°였다. 떨림은 팔을 조립하며 더해진 마찰보다 서보 자체(기어 마찰과 차이에 비례하는 제어)의 성질에 가깝다.
- 끝 자세에서 그 관절의 부하가 오르지 않아, 선이 당겨서 생긴 떨림은 아니다 (0034의 처음 전원 결과).
- 7.5°/s(관절 돌리기)와 15°/s(어깨 버티기)의 떨림 폭은 비슷했다.
- 지금 서보 설정: P 32, D 32, I 0. 불감대는 STS3250 0, STS3215와 ST-3120은 메모리 표 초기값(1). 최소 기동 토크(24)는 STS3215 16, 나머지 0. 실행 루프는 토크를 켤 때 서보 안 가속 상한(41)을 11(1,100 step/s², 약 97°/s²), 목표 속도(46)를 512 step/s(45°/s)로 쓴다 (궤적 한계의 1.5배, 0032).

## 검토한 대안

| 갈래 | 대안 | 장점 | 단점 |
|---|---|---|---|
| 떨림 | A. 서보 P 게인 올리기 (D도 같이 본다) | 같은 마찰을 더 작은 차이로 넘어서, 떨림 폭, 뒤처짐, 처짐이 같이 준다 (어림) | 너무 높으면 백래시와 관성 때문에 버틸 때 흔들리거나(헌팅) 설 때 넘친다. 관절마다 짐과 관성이 달라 값이 다를 수 있다 |
| | B. 서보 안 가속 상한(41) 없애기 (0) | RAM 값이라 바로 바꾸고 되돌린다. 미끄러져 따라잡을 때 서보 안 프로파일이 막고 있을 수 있다 (미끄러질 때 속도가 목표의 두 배인 200 step/s까지 오른다) | 목표가 박자마다 바뀔 때 서보 펌웨어가 프로파일을 어떻게 다시 짜는지 모른다 (메모리 표에 없다). 큰 목표 뜀은 실행 루프가 이미 거른다 (0032) |
| | C. 최소 기동 토크(24), 불감대(26, 27) | 정지 마찰을 넘을 힘을 미리 더해 서 있는 동안 차이가 덜 벌어진다 | 지금 값(STS3215 16)으로도 떤다. 키우면 버틸 때 작은 차이마다 툭툭 친다. 잠근 채 바꿔 보기는 지금 로봇 관절에 P·I·D와 응답 지연만 받는다 ([0024](0024-servo-bus.md)) |
| | D. 목표를 움직이는 쪽으로 앞당겨 보내기 (컨트롤러의 속도 앞먹임) | 서보 설정 없이 뒤처짐을 줄인다. 궤적의 속도는 이미 안다 | 서보가 받는 차이의 꼴은 같아 스틱슬립은 남는다. 관절과 자세마다 앞당길 양이 다르다 |
| | E. 관절 마찰 줄이기 (기계) | 원인 쪽을 고친다 | 시험대의 J5도 같아 서보 몫이 크다. 관절을 풀어야 한다 |
| | F. 빨리 움직이기 | 할 것이 없다 | 정밀하게 자리 잡기와 직선 이동은 느리다. 7.5°/s와 15°/s에서 비슷했다 |
| | J. 서보를 일정 속도 모드로 두고 컨트롤러가 위치를 감기 | 서보 안 속도 고리에 적분(speed I)이 있어 느린 속도에서 마찰을 넘기 쉬울 수 있다 | 서보의 위치 고리와 각도 한계를 쓰지 못하고, 통신이 끊기면 서보가 마지막 속도로 계속 돌 수 있다 (메모리 표에 끊김 시간 칸이 없다. [0009](0009-control-architecture.md)의 안전과 맞지 않는다). 위치를 100 Hz 바깥에서 감아 느리다. 뺐다 |
| 처짐 | G. 서보 I 게인 (23) | 서보 안에서 차이를 0으로 모은다. 움직일 때 뒤처짐도 준다 | 정지 마찰과 같이 있으면 버틸 때 넘었다 돌아오기를 되풀이할 수 있다 (헌팅). 버틸 때만 켜는 식으로 다루기 어렵다 |
| | H. 실행 루프의 처짐 보정 (있는 바깥 적분, 0032) | 이득과 최대(3°)를 로봇 설정에서 고르고, 읽은 위치로 목표를 고친다. 언제 켤지를 컨트롤러가 정한다 | 100 Hz 바깥 고리라 느리다. 마찰 때문에 한 칸씩 넘나들 수 있다 |
| | I. 처짐을 미리 셈해 목표에 더하기 (중력 모델) | 헌팅이 없다 | 관절마다 처짐과 버팀 토크의 비를 재서 맞춰야 하고, 짐이 바뀌면 틀린다 |

## 결정

서보 쪽부터, 값싸고 되돌릴 수 있는 것부터 팔에서 재서 고른다. 재기 전에 통과 기준과 순서를 정해 둔다.

- 통과 기준 (관절마다, [0012](0012-precision-metrics.md)의 목표에서):
  - 처짐: 버티는 동안 |읽은 위치 - 목표|가 1칸(0.088°) 안. 반복 정밀도 목표(X, Y 각 0.7 mm)는 관절이 ±0.9칸 안에 설 때 되고, 상대 정확도 목표는 처짐 보정이 있어야 된다.
  - 헌팅 없음: 버티는 5초 동안 위치 폭이 1칸 안 (같은 까닭. 한두 박자 튀어 읽힌 값은 거른다).
  - 떨림: 움직이는 동안 1초 폭이 2칸(0.18°) 안. 반지름 30 cm에서 약 1 mm로, 상대 정확도 목표와 같은 크기다 (가정: 움직이는 길도 1 mm 크기면 된다. 직선 이동이나 카메라로 보며 움직일 때). 지금 가운데 값이 2 ~ 3칸이라, 가장 큰 값(J3 0.67°)을 이 안으로 줄이는 것이 목표다.
  - 넘침: 움직임이 끝난 뒤 움직이던 쪽으로 목표를 지나친 양이 2칸 안 (처짐이 그쪽이면 처짐만큼 선 자리에서 더 간 양).
  - 열과 부하는 같은 순서를 지금 설정으로 돌린 값과 견주어 보인다. 기준은 두지 않고, 눈에 띄게 늘면 그 설정을 접을지 같이 정한다.
- 순서 (앞에서 통과하면 뒤는 하지 않는다):
  1. 지금 설정으로 한 번 (기준선).
  2. B: 서보 안 가속 상한 0과 지금 값(11).
  3. A: P 32 → 48 → 64 (D 32), 넘침이나 헌팅이 나면 D 64.
  4. 처짐: H(이득 셋쯤)와 G(I 게인 둘쯤)를 같은 순서로 견준다. 0012가 남긴 갈림길이다.
  5. 떨림이 그래도 기준을 넘으면 C, 그다음 D.
  6. 그래도 넘으면 관절마다 움직이기 시작하는 데 드는 출력(정지 마찰)을 재서 E를 본다.
- 재는 법: J1(중력 없음), J2, J3(중력 큼)을 하나씩, 홈 자세 둘레에서 ±20°를 7.5°/s와 15°/s로 왕복하고 끝마다 5초 버틴다. J3만 가운데가 90°다: 홈 자세(110°)에서 더 접으면(130°) 그리퍼가 위팔에 닿고, 90°는 아래팔이 거의 수평이라 J3에 중력이 가장 크다. 짐은 없다. 처짐은 어깨 버티기의 30 cm 자세(짐 150 g)에서 15초 버티며 다시 본다. 손목(J4 ~ J6)은 고른 값으로 같은 왕복을 한 번 돌려 확인만 한다. 지금 설정과 고른 설정의 J1 ~ J3 왕복은 그리퍼 끝을 휴대폰으로 옆에서 찍어(받침에 고정, 60 fps 이상, 뒤에 자) 기록에 잡히지 않는 몫까지 떨림이 줄었는지 본다: 서보 센서는 서보 축을 재서, 서보와 출력 부품 사이의 헐거움과 링크가 휘는 것은 기록에 없다. 설정 하나에 2분 30초쯤(쉬는 자세에서 떠나고 돌아오는 것까지), 하루에 30 ~ 40분 어림이다.
- 설정은 잠근 채 바꿔 보기(`write_trial`, 바로 듣고 서보 전원을 끄면 사라진다, 0024)로 바꾸고, 고른 값만 로봇 설정의 `[joints.<이름>.registers]`에 적어 값 적용으로 굽는다.
- 만든 것 (2026-11-28, 실물 없이 만들고 시뮬레이션에서 끝까지 돌려 봤다):
  1. 시험 순서 (`data/scripts/tuning/`): 위 왕복 `arm.toml`(J1 ~ J3)과 `wrist.toml`(J4 ~ J6), 짐을 든 처짐 `sag.toml`. 셋 다 쉬는 자세에서 떠나 쉬는 자세로 돌아와 토크를 끈다. 한 순서에서 두 빠르기로 오가려고 움직이기마다 빠르기(`speed_percent`)를 줄 수 있게 했다 ([0034](0034-first-power-tools.md)의 실행 명령). 부딪힘 검사, 왕복의 꼴, 시뮬레이션 끝까지는 `cargo test -p horibot-controller --test scripts`가 본다. 중간에 세우면 지금 자리에서 `data/scripts/to-rest.toml`이나 `to-rest-via-home.toml`(홈 자세를 거친다) 가운데 부딪힘 검사를 지나는 쪽으로 돌아간다: 손목을 홈 자세보다 더 돌린 자리(J4 165°, J5 110°)에서는 곧은 길이 위팔을 스치고, 쉬는 자세 바로 둘레에서는 홈 자세를 거치는 길이 선반을 긁는다. 측정 자세마다 둘 가운데 하나는 지나는지 같은 시험이 본다.
  2. 실행 명령의 시험 값 `--trial [<관절>,…:]<이름>=<값>` (`crates/controller/src/trial.rs`): 서보 게인 P(16 ~ 64), D(32 ~ 64), I(0 ~ 4), 서보 안 가속 상한(0 또는 토크를 켤 때 쓰는 값 11 ~ 254), 실행 루프의 처짐 보정 이득(0 ~ 5/s). 받는 범위는 위 순서를 덮는 만큼으로 좁게 두어 팔을 망가뜨릴 값은 받지 않는다 (D는 흔들림을 잡는 몫이라 지금 값 밑으로 내리지 않는다). 토크를 켜고 지금 자리를 붙잡은 뒤에 쓰고(켤 때 서보의 EEPROM 값을 로봇 설정과 견주므로), 순서가 끝나면(마쳤거나, 사람이 세웠거나, 고장) 쓰기 전 값으로 되돌린다. 그래서 버틸 때 흔들리면 B로 세워 처음 값으로 돌아가고, 다음 실행이 시험 값을 물려받지 않는다. 쓰기 전 값, 쓴 값, 되돌렸는지는 실행 기록(meta.json)의 `trial`에, 모든 서보의 게인과 가속 상한은 `servo_values`에 남는다. 최소 기동 토크와 불감대는 순서 5에 갈 때만 넓힌다.
  3. 지표 분석 `tools/run_metrics.py`: 기록마다 관절별 떨림(빠르기마다), 뒤처짐(모든 움직이기의 가장 큰 값까지), 처짐, 헌팅, 넘침을 기준과 견주어 통과와 넘음으로 보이고, 열(온도 오름)과 부하를 같이 보인다. 기록을 여럿 주면 첫 기록을 기준으로 한 줄씩 견준다. 표준 라이브러리만 써서 컨트롤러 파이에서 바로 돈다 (`ssh hori1 'python3 - <기록 폴더> ...' < tools/run_metrics.py`). 처짐 보정을 켜면 서보에 쓴 목표가 목표와 달라져서, 실행 기록에 실행 루프가 노린 자리(`target` 칸)를 더했고 지표는 그것으로 잰다.
- 따라가기 오차 기준(10°)은 고른 설정에서 움직일 때의 뒤처짐을 다시 재서 줄인다 (부딪힘을 더 빨리 안다).

## 근거

- 떨림의 꼴(출력이 차이에 비례해 커졌다가 미끄러지며 떨어짐, 버틸 때는 조용함)은 정지 마찰이 움직이는 동안의 마찰보다 큰 관절을, 차이에 비례해 힘을 내는 서보가 천천히 끄는 스틱슬립이다. 마찰이 같아도 서보가 차이에 얼마나 세게 답하는지(P), 미끄러질 때 무엇이 막는지(서보 안 가속 상한, D), 차이를 모으는지(I)에 따라 폭과 뒤처짐이 바뀐다. 그래서 서보 설정부터 본다.
- 시험대의 J5도 같은 폭으로 떨어서, 관절을 풀어 마찰을 줄이는 일(E)은 서보 설정으로 안 될 때만 한다.
- 잠근 채 바꿔 보기는 EEPROM을 쓰지 않고 서보 전원을 끄면 처음으로 돌아가서, 시험한 값이 남을 위험이 없다.
- 다른 사람의 설정: LeRobot의 SO-100 팔 코드가 STS3215의 P를 32에서 16으로 낮춘다고 기억한다 (흔들림을 줄이려고, 원문은 확인하지 않았다). 그쪽 흔들림이 버틸 때의 흔들림이면 P를 올리는 쪽은 헌팅을 꼭 같이 봐야 해서, 통과 기준에 헌팅을 넣었다.

## 영향

- 다음 실물 날 위 순서대로 잰다: 설정마다 `arm.toml`(처짐을 볼 때는 `sag.toml`)을 `--trial`로 돌리고, 기록을 `tools/run_metrics.py`로 지금 설정의 기록과 견준다. 고른 값과 잰 값은 이 기록에 더한다.
- 고른 값은 `data/robot.toml`의 `[joints.<이름>.registers]`, `[run_loop]`의 `sag_gain_per_s`와 `following_error_deg`에 적고, 0012와 0032의 "다 만든 팔에서" 칸을 이 기록으로 닫는다.
- 시뮬레이션 게인을 실물 처짐에 맞추는 일([0033](0033-planning-and-simulation.md))은 값을 고른 뒤에 한다.
