# 0036. 작업 안내 사이트

- 상태: 채택
- 날짜: 2026-11-16

요구, 범위, 화면, 구조, 라이브러리, 데이터 모델, 옮기는 계획을 정했다 (2026-11-16). 만들기는 [옮기는 계획](#옮기는-계획)의 1부터 한다.

## 배경

- 3D가 필요한 안내(조립, 설계 보기, 출력, 재기·시험, 배선)를 페이지마다 따로 만들어 왔다 (STS 관절 구조, 어깨, J1, 손목 끝, 그리퍼, 팔 전체, 출력 안내). 주소, 조작, 만든 방식(레포 코드, 임시 폴더의 손 편집)이 제각각이다.
- 안내는 화면을 보며 판단 없이 따라 해서 끝낼 수 있어야 한다 ([design.md](../design.md#설계-방식)의 조립 가이드).
- 사진과 잰 값을 휴대폰에서 PC의 Claude 대화로 옮기는 데 손이 많이 갔다: 휴대폰으로 찍고, 메신저로 PC에 옮기고, 대화창에 붙여 넣었다.

## 결정: 요구, 범위, 화면

### 목적: 화면만 보고 틀리지 않고 끝까지

이 사이트의 목적은 화면만 보고 판단이나 짐작 없이, 틀리지 않고 끝까지 따라 하게 하는 것이다 (조립, 재기, 배선, 출력). 모든 판단은 이 목적에 맞춘다. 목적에 필요한 품질(사진 원본, 3D와 움직임의 자세함, 글의 자세함)은 꾸밈, 기능 수, 저장 공간, 메모리 때문에 낮추지 않는다. 그러려면 안내가 자세하고 쉬워야 하고, 그 기준은 아래와 같다.

- 한 단계에는 손동작 하나만 둔다 (부품 하나 끼우기, 나사 한 묶음 조이기, 선 하나 꽂기).
- 시작하기 전에 준비물 단계를 둔다: 이 안내에 쓰는 부품, 나사(규격과 개수), 공구를 한 화면에 모아 보이고, 다 꺼내 놓고 시작한다.
- 부품은 한글 이름, 색과 모양, 파일 이름으로 알아보게 한다. 비슷한 부품은 다른 점을 짚는다. 나사는 그림끼리 같은 비율로 그려 길이를 견주게 한다. 길이를 모르는 나사는 자나 캘리퍼스 옆에 놓고 찍어 Claude에게 묻는다. 화면에 대 보는 실제 크기 그림은 쓰지 않는다: 모니터, 해상도, 배율, 브라우저 확대가 바뀔 때마다 다시 맞춰야 하고, 나사를 하나씩 화면에 대 보는 것보다 묻는 편이 빠르다.
- 방향(위아래, 앞뒤, 어느 면이 어디를 보는지)은 3D 화살표와 글로 같이 보인다.
- 단계마다 "다 하면 이렇게 보인다"를 보이고, 맞게 됐는지 확인할 것을 적는다.
- 틀리기 쉬운 곳과 틀리면 다시 뜯어야 하는 곳은 그 단계에 미리 경고한다 (선을 먼저 꽂기, 너트 방향, 세게 조이지 않기 같은 것).
- 쉬운 말로 쓴다. 전문 용어 없이 한 문장에 할 일 하나.
- 막히면 할 일을 정해 둔다: 안 들어가거나 이상하면 억지로 하지 말고 사진을 보낸다 (아래 사진).
- 실제로 써 보고 고친다. 첫 관절을 지금의 3D 페이지로 조립하며 헷갈린 곳을 첫 설명서에 넣고, 그 뒤로도 막힌 단계의 메모를 보고 안내를 고친다.

### 보는 자리와 쓰는 법

- 작업대 옆 PC 모니터로 본다. 손이 부품과 공구로 바쁘므로 단계는 키 하나(다음은 스페이스나 →, 이전은 ←)나 큰 버튼으로 넘긴다. 메모를 치는 동안에는 키가 단계를 넘기지 않는다.
- 주소 하나, 3D 뷰어 하나, 조작 하나로 모든 안내를 본다. 새 안내는 같은 주소에 더한다. 처음 화면에는 종류별(조립, 출력, 재기·시험, 배선, 설계 보기) 안내 목록, 안내마다 진행(끝낸 단계 수, 예: 3/8), 이어서 하기를 둔다.
- 진행은 단계마다 "다 하면 확인" 칸으로만 정한다. 칸을 다 누른 단계가 끝낸 단계이고, 안내를 고르거나 이어서 하면 아직 안 끝낸 첫 단계로 간다. 조립하다 재기나 출력으로 옮겼다 돌아와도 그 자리에서 이어진다. 단계를 눌러 보기만 해서는 아무것도 저장하지 않는다 (미리 본 단계가 끝낸 단계나 멈춘 자리로 남지 않게). 확인 칸은 저장되어 Claude도 읽는다.

### 범위

- 첫 결과물: STS 관절 조립 설명서. 같은 관절이 손목에 되풀이되어 그대로 다시 쓴다.
- 그다음 옮겨 올 것과 차례는 [옮기는 계획](#옮기는-계획)에 있다.
- 하지 않는 것: 웹서버와 로그인, 휴대폰에 맞춘 3D 화면, 로봇을 움직이는 화면(펜던트는 따로 만든다).

### 안내 화면

모든 안내가 같은 틀을 쓴다. 정보마다 칸이 하나이고, 칸마다 자리가 정해져 있다. 화면은 첫 관절 앞부분의 실제 단계로 만든 시안 페이지로 정했다.

- 3D가 가운데를 채운다. 단계마다 부품을 손에 드는 방향으로 놓는다 (예: 베어링을 넣을 때는 손목 몸통의 뒤쪽이 위). 이번 부품만 색을 입히고, 끼우는 방향의 화살표와 움직임을 되풀이한다. 움직임이 멈춘 끝 장면이 "다 하면 이렇게 보인다"이다.
- 3D 위에는 움직임 막대(멈춤, 끌어 보기, 한 칸씩, 빠르기 1×·½×·¼×, 다 된 모습)와 도구(몸통을 반으로 자르기, 반투명, 처음 시점, 이름표 끄기, 칸 숨기기)를 둔다. 부품을 두 번 누르면 숨긴다.
- 방향 이름표(뒤, 발 쪽 같은), 부품 이름표, 손볼 자리 번호(①, ② 같은)는 3D 그림 안에 그리지 않고 글자로 띄운다. 이름표가 부품을 가릴 때가 있어서, 부품 이름표와 방향 이름표는 버튼이나 L 키로 끄고 켠다. 끈 상태는 PC마다 기억한다. 손볼 자리 번호는 글에서 가리키므로 끄지 않는다.
- 서보가 나오는 안내는 어느 서보인지 ID를 이름에 쓴다 (예: "서보 STS3215 · ID 5"). 서보마다 ID 이름표가 붙어 있다. 만들기가 ID 없는 서보를 막는다.
- 칸은 3D 위에 뜬다. 처음 자리는 왼쪽에 단계(번호와 이름)와 이번에 쓰는 것, 아래 가운데에 할 일, 오른쪽에 주의, 다 하면 확인, 막히면, 이 단계 메모다. 3D는 칸 바깥의 빈 곳 가운데에 맞춘다.
- 이번에 쓰는 것: 부품 그림(설계 형상으로 그린다), 한글 이름, 개수, 색과 판, 파일 이름과 복사 버튼. 나사와 너트는 그림끼리 같은 비율로 그린다.
- 준비물 단계에서는 3D 자리에 그 안내의 부품, 나사, 공구를 모두 펼쳐 보인다.
- 칸은 제목 줄을 잡아 끌면 왼쪽 줄, 오른쪽 줄, 아래 가운데 가운데 가까운 곳에 붙는다. 제목 줄을 누르면 접힌다. 주의와 다 하면 확인은 단계마다 내용이 바뀌어서, 접어 두어도 다음 단계에서 다시 펼친다. H 키로 칸을 잠깐 다 숨긴다. L 키로 이름표를 끄고 켠다. 옮긴 자리와 접은 상태는 PC마다 기억하고, 처음 자리로 돌리는 버튼이 있다.
- 위 막대: 처음 화면, 안내 이름과 "안내 바꾸기"(하던 안내 목록, 고르면 아직 안 끝낸 첫 단계로 간다), 진행(끝낸 단계 수), 마지막으로 저장한 시각.
- 아래: 단계 띠(끝낸 단계에 ✓)와 이전·다음.
- 휴대폰: 칸을 정해진 차례(단계, 할 일, 주의, 이번에 쓰는 것, 확인, 막히면, 메모)로 쌓고 끌지 않는다. 3D는 눌렀을 때만 띄운다.
- 안내마다 한 단계의 뜻:
  - 조립: 조립 동작 하나.
  - 출력: 판 하나. 파일 이름, 필라멘트 색, 시간, 확인할 것, "뽑았다" 표시.
  - 재기·시험: 잴 자리 하나. 3D에 캘리퍼스를 대는 자리를 화살표로 보이고, 찍는 법을 적는다.
  - 배선: 선 하나. 지나는 길과 꽂는 때.
  - 설계 보기: 단계 없이 돌려 본다.

### 작은 불편도 요구로 다룬다

- 화면의 글자는 끌어서 선택하고 복사할 수 있다. 빼는 것은 버튼 글자와, 칸을 끄는 손잡이인 칸 제목 줄뿐이다. 글자를 3D 그림 안에 두지 않고, 단계 이름도 버튼 안에 두지 않는다 (지금 페이지들은 단계 이름을 버튼 안에, 일부 이름표를 3D 그림 안에 두어 복사가 안 됐다).
- 단계 띠나 확인 칸의 글자를 끌어 고를 때는 단계가 넘어가거나 칸이 체크되지 않는다.
- 파일 이름과 경로처럼 자주 복사할 것은 옆에 복사 버튼을 둔다.
- 3D 창을 끌어 돌리는 동작이 옆 카드의 글자 선택을 빼앗지 않는다.
- 이런 것을 PC와 휴대폰에서 직접 써 보는 점검 목록에 넣고, 하나씩 확인한 뒤 넘긴다.

### 사진, 잰 값, 메모

- 사진은 Remote Control 앱 대화창의 카메라로 찍어 보낸다.
- 사진이 오면 Claude가 확인 칸 기록에서 마지막으로 체크한 안내의 아직 안 끝낸 첫 단계를 그 사진의 단계로 본다. 마지막 체크가 오래됐거나 사진이 다른 단계로 보이면 묻는다.
- 재기 단계는 사진이 기본 기록이다. 표시창 숫자와 캘리퍼스 턱이 닿은 자리가 같이 나오게 찍는다. 숫자 칸은 있지만 채우지 않아도 되고, Claude가 사진에서 값과 잰 자리를 읽는다.
- 메모(막힌 곳, 이상한 점)는 안내의 그 단계에 적는다. 저장되어 Claude가 읽는다.
- 남길 사진(잰 값, 안 맞거나 이상했던 곳, 조립하면 가려지는 곳)은 Claude가 그 단계 기록에 붙이고, 잰 값은 값 파일(`data/measured.toml`)에도 적는다. 남길 때마다 한 줄로 알린다.
- 안내 페이지의 사진 올리기는 휴대폰 브라우저로 볼 때의 예비로만 둔다 (앨범에서 여러 장, 원본 그대로).

### 개인정보

- 사진에는 로봇과 관계없는 것(사람, 집 안, 화면, 문서)이 찍힐 수 있다. 기록에는 로봇 일에 필요한 사진만 남기고, 필요하면 그 부분만 잘라 남긴다. 사람이나 개인 물건이 찍힌 사진은 기록에 남기지 않는다.
- 원본 사진의 촬영 정보 가운데 위치는 기록에 붙이기 전에 지운다.
- 사진은 공개 레포에 커밋하지 않는다. 사진은 비공개 아티팩트(안내)와 git에서 뺀 기록 폴더([0022](0022-records-and-sync.md))에만 둔다. 레포에는 숫자와 결론만 적는다.
- 안내 아티팩트는 비공개로 둔다. 다른 사람과 나누려면 그 전에 사진 기록을 빼야 한다.

### 저장 공간과 메모리

사진과 영상은 크기가 커서 저장 공간과 메모리를 놓치기 쉽다. 품질은 낮추지 않고 관리로 푼다.

- 사진은 원본 그대로 안내의 단계 기록에 한 번 저장한다. 같은 사진을 여러 곳에 쌓지 않고, 오래 남길 잰 값의 근거 사진만 기록 폴더에도 둔다.
- 남길 것만 남기고 시험 데이터는 지운다. 아티팩트 한도(문서 25,000개, 파일 하나 20 MB)에 가까워지면 넘기 전에 알린다.
- 3D 형상과 움직임은 안내에 필요한 만큼 자세하게 둔다. 그 안내에 쓰는 것만 불러오고, 다른 안내로 옮기면 앞의 것을 내린다. 휴대폰은 메모와 사진이 주 용도라, 3D는 눌렀을 때만 띄운다.

## 결정: 구조

- 코드는 `horilab_design.guide`(packages/design)에 둔다. 안내가 설계 코드의 형상과 값을 그대로 쓰기 때문이다. 다 옮기면 `horilab_design.pages`는 지운다.
- 네 층으로 나눈다.
  1. 설계 코드(`parts/`): 형상, 조립된 자리, 형상이 정하는 값(너트 홈의 입구와 미는 방향, 손볼 자리 같은 것). 안내는 이 값을 가져다 쓰고 숫자를 따로 적지 않는다.
  2. 안내 정의(`guide/guides/`): 안내 하나가 모듈 하나다. 단계마다 글(할 일, 주의, 확인, 막히면), 나타나는 부품, 움직임, 손에 드는 방향, 이름표를 파이썬 데이터로 적는다.
  3. 만들기(`uv run python -m horilab_design.guide build`): 모든 안내를 읽어 검사하고 `build/guide/`에 페이지 하나(`index.html`)와 데이터 파일(`data/`)을 쓴다. 검사만 할 때는 `check`, 만든 사이트를 브라우저로 점검할 때는 `selftest`다.
  4. 웹 앱(`guide/web/`): 화면 코드(HTML, CSS, JS). 만들 때 `index.html` 하나로 이어 붙인다.
- 올리기: Claude가 `build/guide/`를 아티팩트 "작업 안내" 하나에 올린다. 만들 때 파일마다 해시를 적어 두어, 바뀐 파일만 다시 보낸다.
- 페이지는 지금 보는 안내의 데이터와 형상만 불러오고, 다른 안내로 옮기면 앞의 것을 내린다.
- 쓰면서 생기는 것(확인 칸, 메모, 단계 기록)은 아티팩트의 데이터 저장(db)에, 사진 파일은 아티팩트의 파일 저장(assets)에 둔다. Claude는 둘을 도구로 읽고 쓴다. 진행은 확인 칸에서 셈하고 따로 저장하지 않는다. 칸 자리와 접은 상태는 화면마다 달라서 그 브라우저에만 둔다.
- 페이지는 저장이 없을 때(PC의 파일로 열 때, 시험할 때)도 돌아가고, 저장만 빠진다.

## 결정: 라이브러리

- 3D: three.js r128과 OrbitControls (지금 페이지들과 같은 판, cdnjs와 jsdelivr). 쓰는 기능(메시, 선, 자르는 면, 광선으로 부품 고르기)이 다 있고, 아티팩트의 스크립트 제한 안에서 돈다는 것을 지금 페이지들로 이미 확인했다. 판을 올릴 일이 생기면 시험 페이지로 먼저 확인한다.
- 화면 코드: 프레임워크 없는 JS. 시안 코드에서 시작한다.
- 파이썬: build123d(형상을 삼각형으로)와 표준 라이브러리(base64 묶기). 새 패키지는 들이지 않는다.
- 글꼴: IBM Plex Sans KR, IBM Plex Mono (Google Fonts, 지금과 같다).
- 시험: pytest가 만든 사이트를 작은 로컬 서버로 띄우고, 깔린 크롬(없으면 엣지)을 헤드리스로 열어 자체 점검 모드를 돌린다. 점검 결과(오류, 빈 칸, 못 찾은 부품)는 페이지에 적히고 pytest가 그것을 읽는다. 브라우저나 인터넷(three.js를 받는다)이 없으면 이 시험만 건너뛴다.

## 결정: 데이터 모델

만들 때 쓰는 파일 (`build/guide/`):

- `index.html`: 화면 코드 전부.
- `data/catalog.json`: 안내 목록 (id, 종류, 이름, 단계 수, 파일, 확인 칸이 있는 단계와 판 단계마다 id·번호·짧은 이름·칸 수, 판은 칸 수 0). 처음 화면은 이것으로 안내를 열지 않고 진행을 셈한다.
- `data/guides/<안내 id>.json`: 안내 하나.
  - 부품 목록: 키마다 한글 이름, 종류(출력, 산 것, 나사, 공구), 파일 이름, 색과 판, 나사 그림의 치수, 작은 그림에 쓸 형상.
  - 장면: 놓인 부품 하나하나. 이름, 부품 목록의 키, 형상, 놓는 자리(지금은 옮김만: 형상 상자 가운데의 자리), 자식과 같이 도는지, 자식 몸통 속 관절(둘째 관절, 예를 들어 J5 장면의 J6)과도 같이 도는지. 둘째 관절이 있는 안내는 그 축(지나는 점과 방향)을 가진다. 관절 각에 따라 모양이 바뀌는 선(테에 감기는 서보 선)은 형상 대신 관절 각마다의 꺾은선을 담고, 화면이 지금 관절 각의 앞뒤 모양 사이를 이어 납작한 선으로 그린다. 선 하나는 커넥터에서 커넥터까지 이어 그린다: 모양을 모르는 바깥 고리도 어림으로 잇고, 같은 선을 토막으로 나눠 그리지 않는다. 토막으로 그린 선을 서로 다른 선으로 읽어 잘못 이은 일이 있었다 (2026-11-19, 손목 끝 조립의 J5 → J6 선).
  - 단계: id, 종류(준비물, 작업, 판, 잴 자리, 끝), 짧은 이름, 제목, 할 일, 주의, 확인, 막히면, 이번에 나타나는 부품(그 가운데 움직이지 않는 것), 쓰는 공구, 따로 놓고 하는 단계에서 보일 부품, 따로 놓는 자리와 방향, 움직임(부품, 시작 자리까지의 거리, 늦춤), 관절 각과 돌려 보일 범위(둘째 관절도 따로, 첫째를 돌린 뒤 돌린다), 손에 드는 방향, 다가가 볼 배율과 가운데(작은 자리를 볼 때), 자르고 반투명하게 할 몸통, 방향 이름표, 부품 이름표, 손볼 자리. 판 단계는 판 그림, 3MF 이름, 시간, 필라멘트 색을, 잴 자리 단계는 값 이름, 단위, 찍는 법을 더 가진다.
  - 설계 보기 안내는 단계 대신 펼치는 방향, 관절이 도는 범위, 숫자 표, 이 구조로 잡은 까닭, 남은 것을 가진다.
- `data/meshes/<형상 id>.json`: 형상 하나. 꼭짓점은 형상 상자의 가운데에서 잰 0.01 mm 칸의 정수(int16), 삼각형은 꼭짓점 번호이고, 둘을 base64로 묶는다. id는 내용의 해시라 형상이 그대로면 파일 이름도 그대로다. 옮기기만 다른 같은 형상(나사, 너트)은 한 번만 내보내고 장면에는 놓는 자리만 둔다. 안내끼리 같이 쓴다.
- 판 그림은 PNG 파일로 둔다 (`data/prints/<묶음>/`, 레포의 같은 자리에서 옮긴다). 출력 안내의 단계는 판 하나다: 3MF 이름과 폴더, 색, 프리셋, 시간, 무게, 판 그림, 부품(한글 이름, STL 이름, 개수, 높이). 조립 안내의 출력 부품은 자기 묶음을 담은 출력 안내의 판(출력 안내 id, 판 단계 id, 판 번호, 개수)을 가진다. 앞의 다른 묶음에서 뽑아 둔 부품(예: 선 시험 때 뽑은 서보 받침)은 안내에 따로 적어 두고 판 없이 보인다.

만들 때 셈하는 것 (손으로 적지 않는다):

- 보이는 부품: 앞 단계까지 나타난 부품을 그대로 둔다. 따로 놓고 하는 단계만 보일 부품을 좁힌다.
- 이번에 쓰는 것: 그 단계에 나타나는 부품을 부품 목록의 키로 세고 공구를 더한다. 준비물은 모든 단계의 것을 더한다. 그래서 개수가 3D와 어긋나지 않는다.
- 검사: id가 겹치지 않는지, 단계가 가리키는 부품과 형상과 공구가 다 있는지, 움직이는 부품이 보이는지, 할 일과 확인이 비지 않았는지, 파일 이름이 출력 묶음에 있는지.

쓰면서 쌓이는 것 (아티팩트 db):

- `checks/<안내 id>`: 단계 id마다 확인 칸의 체크(`marks`)와 마지막으로 바꾼 시각(`at`). 끝낸 단계, 진행, 이어서 할 단계는 여기서 셈하고 따로 저장하지 않는다. 단계를 눌러 보기만 해서는 아무것도 쓰지 않는다.
- `notes/<자동 id>`: 안내, 단계, 글, 시각, 사진(있으면 파일 id).
- `records/<자동 id>`: Claude가 남기는 단계 기록. 안내, 단계, 종류(사진, 잰 값), 파일 id, 값, 설명, 시각. 잰 값은 `data/measured.toml`에도 적는다.
  - 판 기록: 종류 `printed`(그 판 단계를 뽑았다)와 `bad`(못 쓰는 부품: STL 이름, 개수, 까닭). 출력 안내의 진행과 조립 안내 준비물의 출력 부품 상태(쓸 수 있는 개수 = 뽑은 판의 개수 − 못 쓰는 개수)는 이것으로 셈한다. 시각을 모르면 날짜만 적는다.
- 단계는 순서 번호가 아니라 id로 가리킨다. 안내를 고쳐 단계를 끼워 넣어도 확인 칸과 메모가 제 단계에 남는다.

브라우저마다 (localStorage): 칸 자리, 접은 상태, 쓰다 만 메모.

## 옮기는 계획

1. 틀과 첫 관절 조립 안내: `horilab_design.guide`(모델, 형상 내보내기, 만들기, 검사, 웹 앱, 자체 점검)를 만들고, 첫 관절을 준비물부터 영점까지 손동작 하나씩으로 나눠 넣는다. 화면은 시안 코드에서, 단계 글은 지금 3D 페이지와 시안에서 옮긴다. 새 아티팩트 "작업 안내"에 올리면서 데이터 파일 불러오기와 db 쓰기를 실제로 확인하고, 주소를 status.md와 CLAUDE.md에 적는다. 이 결정 기록은 여기서 같이 커밋한다.
2. 출력 안내: 판마다의 출력 안내를 판 단계로 옮긴다 (plan.json에서 만든다). 다음 판부터 이것으로 뽑는다.
   - 판 계획(plan.json)과 판 그림은 레포의 `data/prints/<묶음>/`에 둔다. 출력 준비 도구가 낸다. 3MF는 만든 PC의 `build/print/<묶음>/`에만 있다. 묶음은 판을 뽑는 집 PC에서 만들고, 사이트는 어느 PC에서 만들어도 모든 출력 안내가 들어가야 하며, 판 계획은 뽑은 판의 기록이기도 하다. 판 계획과 판 그림은 판 하나에 수십 KB다.
   - 출력 안내는 `guide/guides/prints.py`에 묶음 이름의 목록으로 정한다. 단계 id는 `<묶음>-<묶음 안의 차례>`, 판 번호는 묶음을 이어 센다.
   - 판 화면은 판 그림이 기본이다. 이 판의 부품을 누르면 그 부품 하나를 3D로 보이고, 다시 누르면 판 그림으로 돌아간다. 형상은 사이트를 만들 때 판 계획에 적힌 모듈과 부품 이름으로 지금 설계 코드에서 만들어 뽑는 방향에 놓는다. 그래서 뽑은 뒤 고친 부품은 뽑은 것과 조금 다를 수 있다.
   - 할 일에는 판마다 다른 것(필라멘트 색과 판 종류, 3MF 이름, 프린터 화면에서 볼 파일 이름 끝)만 적는다. 자르는 설정은 도구가 정해 두어 늘 같다. 슬라이스 뒤에 경고가 뜨면 보내지 않고 알리는 것은 주의에 둔다.
   - 판을 뽑았는지와 못 쓰는 부품(휨, 깨짐, 안 맞음, 조립하다 부러짐)은 사용자가 대화창에 글이나 사진으로 알리고 Claude가 db에 적는다. 화면에 누를 칸을 늘리지 않고, 화면은 보여 주기만 한다.
   - 출력 안내는 판마다 뽑았는지와 못 쓰는 부품을, 조립 안내의 준비물은 출력 부품마다 쓸 수 있는지와 다시 뽑을 판을 보인다 (누르면 그 판으로 간다). 조립을 막지는 않는다.
   - 다시 뽑을 판은 Claude가 모자란 부품만 모아 출력 준비 도구로 만들고 출력 안내에 더한다.
   - 뽑은 부품은 그때의 파일과 같이 적어, 설계가 바뀌어 달라진 부품을 찾는다. 다시 뽑을지는 사용자와 정한다.
3. 설계 보기: 관절 페이지들(STS 관절, 어깨, J1, 손목 끝, 그리퍼)과 팔 전체를 옮긴다. 펼치기, 관절 돌리기, 숫자 표, 까닭, 남은 것을 칸으로 둔다.
4. 재기, 배선, 영점 안내는 그 일을 할 때 더한다. 다른 관절의 조립 안내는 그 부품을 설계할 때 조립 순서와 같이 쓴다.
5. 옮길 때마다 문서의 옛 페이지 주소를 바꾸고, 옛 아티팩트는 사용자에게 묻고 지운다. 다 옮기면 `horilab_design.pages`와 CLAUDE.md의 페이지 명령을 지운다.

## 근거

- 한 사이트, 한 뷰어: 안내마다 조작과 주소를 다시 익히지 않고, 설계 코드에서 같은 방식으로 만들어 부품을 고치면 안내도 다시 만들기만 하면 된다.
- 사진 길: 2026-11-16에 시험 페이지로 안드로이드에서 확인했다. Remote Control 화면 안의 페이지는 사진을 고르지 못했고, 휴대폰 크롬에서 카메라를 띄우면 메모리 부족으로 브라우저가 꺼졌고, 앨범에서 고르기는 되었고(2400 픽셀로 줄인 사진에서도 작은 글자가 읽혔다), Remote Control 대화창의 카메라는 원본이 그대로 왔다.
- 단계 기록: 사진마다 안내와 단계를 말하지 않아도 되게, 사용자가 직접 누른 확인 칸(아직 안 끝낸 첫 단계)으로 어느 단계인지 본다. 화면을 연 기록은 쓰지 않는다: 미리 보기만 한 단계가 지금 단계나 끝낸 단계로 남는다.
- 화면: 시안 페이지에서 첫 관절 앞부분(준비물, 실 걷기, 베어링부터 멈춤 기둥까지)의 실제 단계로 배치 넷을 견줘 골랐다. 정보마다 자리가 정해진 배치가 한눈에 읽혔다.
- 구조와 데이터 모델: 안내 정의를 설계 코드 옆 파이썬에 두고, 보이는 부품과 쓰는 것의 개수를 만들 때 셈한다. 형상이나 단계를 고쳐도 3D, 목록, 글이 서로 어긋나지 않고, 어긋나면 만들 때의 검사가 막는다.
