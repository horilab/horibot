# 0039. 카메라 영상: 압축 없이 원래 형식으로 보내고, 시계 차이는 왕복으로 잰다

- 상태: 채택
- 날짜: 2026-11-22

## 배경

- 비전 처리(AI 인식)는 PC가 하고, 카메라 파이는 D405 영상을 PC로 보내기만 한다 ([0025](0025-controller-on-pi.md), [software.md](../software.md#하드웨어-연결)). 영상 압축과 시계 맞추기는 카메라를 구현할 때 정하기로 했다 ([0008](0008-environment-and-packages.md)).
- D405는 얇은 USB 2 선이라 USB 2로 잡힌다 ([0031](0031-wiring.md#d405-선)). 뎁스와 컬러를 같이 켤 때 가장 큰 모드는 640×480 30장과 1280×720 5장이다.
- 그래서 카메라가 내는 것을 압축 없이 보내, PC가 빠짐없이, 늦지 않게 받는지 쟀다 (2026-11-22, hori2 → PC, 모드마다 10분). 통과 기준과 모자랄 때 고를 길은 재기 전에 정했다. 시험 프로그램과 기록은 `records/camera/2026-11-22_162708_d405-stream-hori2/`에 있다.

## 검토한 대안

| 갈래 | 대안 | 장점 | 단점 |
|---|---|---|---|
| 형식 | 카메라가 USB로 내는 그대로 (뎁스 Z16, 컬러 YUYV), 압축 없음 | 파이가 거의 일하지 않는다. 값이 그대로이고 늦음이 가장 짧다 | 랜을 많이 쓴다 (640×480 30장에서 약 295 Mbit/s) |
| | 파이에서 압축 (뎁스는 무손실 lz4나 zstd, 컬러는 JPEG) | 랜을 몇 분의 일로 줄인다 | 파이 CPU와 늦음이 늘고, 컬러에 손실이 생긴다. 압축 값을 따로 정해야 한다 |
| | 동영상 압축 (H.264) | 랜을 가장 적게 쓴다 | 뎁스 값이 망가진다. 늦음이 는다 |
| | 파이에서 컬러를 RGB로 바꿔 보냄 | PC가 바꿀 일이 없다 | 1.5배 크고 파이 CPU를 쓴다 |
| 시계 | 시계 맞추기 프로그램(NTP)으로 PC 시계를 파이에 맞춤 | 받는 프로그램이 할 일이 없다 | PC마다 설정해야 하고, Windows에서 얼마나 맞는지는 확인하지 않았다 |
| | 받는 프로그램이 왕복으로 파이와 PC의 시계 차이를 잼 | 설정할 것이 없다. 오차를 같이 안다 (시험에서 0.5 ms 안) | 받는 프로그램에 시계 재기가 들어간다 |

## 결정

- 카메라 파이는 카메라가 USB로 내는 형식 그대로(뎁스 Z16, 컬러 YUYV) 압축 없이 보낸다. zmq PUB/SUB 메시지 하나에 [머리 JSON, 뎁스 바이트, 컬러 바이트]를 담는다. 컬러를 RGB로 바꾸는 일은 PC가 한다.
- 머리에는 장 번호(뎁스, 컬러), 찍은 때, 파이가 받은 때, 보낸 때를 넣는다. 시각은 모두 파이 시계다. 찍은 때는 노출 가운데로, librealsense 전역 시각(`get_timestamp()`, 기본으로 켜져 있다)에서 `frame_timestamp − sensor_timestamp`(노출의 반)를 뺀 값이다.
- PC는 0.25초마다 파이에 시각을 묻고(REQ/REP), 10초마다 가장 짧은 왕복을 골라 그 점들을 이은 선으로 PC 시각을 파이 시각으로 바꾼다. 오차 한도는 고른 왕복의 절반이다.
- 640×480 30장은 카메라 → 파이에서 10분에 스무 장 남짓(0.1% 아래)이 빠지고, 가끔 같은 뎁스 장이 두 번 온다 (아래). 최신 장을 쓰는 비전에는 지장이 없어 그대로 쓴다. 받는 쪽은 장 번호로 빠진 장과 되풀이된 뎁스 장을 알아채 건너뛴다.

## 근거

시험 결과 (모드마다 10분, 2026-11-22):

| | 640×480 30장 | 1280×720 5장 |
|---|---|---|
| 받은 장 | 18,008장 (30.01장/초) | 3,004장 (5.01장/초) |
| 파이 → PC에서 빠진 장 | 0 | 0 |
| 카메라 → 파이에서 빠진 장 | 뎁스 16, 컬러 10 (아래) | 0 |
| 찍은 때 → 파이가 받음 (중간값) | 49.5 ms | 196.1 ms |
| 파이 → PC (중간값 / p99 / 최대) | 12.9 / 16.0 / 82.0 ms | 35.1 / 37.5 / 65.2 ms |
| 찍은 때 → PC (중간값 / p99 / 최대) | 62.6 / 65.7 / 132.7 ms | 231.4 / 233.8 / 261.4 ms |
| 파이 → PC 중간값의 처음 1분 대비 마지막 1분 | −0.03 ms | −0.12 ms |
| 파이 CPU: 보내는 고리 / 프로세스 (코어 하나 기준), 전체 (네 코어) | 5.5 / 17.4 %, 9.1 % | 1.6 / 5.5 %, 3.1 % |
| 파이 온도 최고 | 39.4 °C | 38.5 °C |
| PC 받는 프로세스 CPU (코어 하나 기준) | 5.3 % | 2.7 % |
| 시계 오차 한도 | 0.47 ms | 0.45 ms |

- 재기 전에 정한 기준: 빠짐 없음, 파이 → PC의 p99가 한 장 간격 안이고 늘지 않음, 찍은 때 → PC의 p99가 640×480 30장 200 ms·1280×720 5장 400 ms 안(사람이 보며 조그할 때와 팔을 세우고 찍을 때를 놓고 잡은 어림), 보내는 고리가 코어 하나의 50% 아래, 파이 80 °C 아래, 시계 오차 한도 1 ms 안.
- 1280×720 5장은 모두 통과했다. 640×480 30장은 빠짐 하나만 걸렸고, 빠진 장은 모두 카메라 → 파이 구간(USB 2)이다. 파이 → PC에서는 빠진 장이 없고, 한 장 간격(33 ms)을 넘은 장이 17장(0.09%)이며 그 뒤에 쌓이지 않았다.
- 640×480 30장에서 빠진 장: 10번은 뎁스와 컬러가 같은 장을 함께 건너뛰었다 (다음 장이 66.6 ms 뒤에 왔다). 6번은 뎁스만 한 장 빠졌고, 그때 librealsense가 앞 뎁스 장을 새 컬러 장과 묶어 내서 같은 뎁스 장이 두 번 왔다. 노출은 내내 32.0 ms(자동)였다.
- 어디서 빠지는지 나누려고, 같은 프로그램을 받는 PC 없이(랜으로 아무것도 나가지 않게) 파이에서만 10분 더 돌렸다. 뎁스 14장, 컬러 11장이 빠지고 같은 뎁스 장이 3번 왔다. 보낼 때와 같은 꼴이라, 빠지는 것은 랜으로 보내는 일과 상관없는 USB 2의 640×480 30장 모드의 성질이다. 랜으로는 고칠 수 없고 선은 이미 정했으므로([0031](0031-wiring.md#d405-선)), 재기 전에 정한 길 가운데 남는 것은 그대로 쓰거나 장 수가 적은 모드를 쓰는 것이다. 지금 쓰임에는 모든 장이 필요하지 않아서 그대로 쓴다.
- 압축하지 않아도 랜은 기가비트의 3분의 1쯤을 쓰고, 파이의 보내는 고리는 코어 하나의 6% 아래였다. 압축은 늦음과 파이의 일만 늘린다.
- 시계는 왕복으로 0.5 ms 안에 맞았다. 파이 시계는 chrony가 고치는 시계라 한 직선에서 벗어날 수 있어서(640×480 시험의 10분 동안 최대 2.2 ms), 고른 점들을 꺾은선으로 잇는다.

## 영향

- 카메라 파이 프로그램을 이 방식으로 만들었다 (2026-11-28). 보내는 쪽은 `pi/camera/send.py`다 (장이 5초 동안 오지 않으면 카메라를 다시 연다). 메시지 형식과 PC 쪽 받기(장 번호로 빠진 장과 되풀이된 뎁스 장 세기, 왕복 시계 맞추기)는 `packages/camera`, PC에서 보는 창과 1초마다의 저장은 `tools/d405_view.py`다. 보는 창의 OpenCV는 PC에만 깐다. pyrealsense2 2.59.2는 aarch64 리눅스 판이 Python 3.12용만 있어서 카메라 파이 프로그램은 3.12로 묶었다. 켜지면 저절로 도는 것은 아직이다 ([status.md](../status.md)의 미룬 일).
- 늦음의 대부분은 카메라 → 파이(USB 2) 몫이다. 랜으로는 줄일 수 없다.
- 팔 자세와 장을 맞추려면(움직이며 찍기, 멈춘 뒤의 장 고르기) 컨트롤러 파이와 카메라 파이의 시계도 맞아야 한다. 그 일을 할 때 정한다.
- 모든 장이 꼭 있어야 하는 일(장을 빠짐없이 모으는 기록 같은 것)이 생기면, 그때 장 수가 적은 모드(640×480 15장 등)를 10분 재 본다.
- PC를 와이파이로 잇거나, 카메라를 더하거나, 영상 모드를 바꾸면 다시 잰다.
